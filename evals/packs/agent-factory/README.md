# Agent Factory evaluations

`contracts.eval.ts` runs five offline checks in the existing Eval Pilot engine: portable metadata, the 600-word project body budget, contained direct references, package/marketplace identity, migration fields, and dated host boundaries.

```powershell
node .\scripts\run-evals.mjs agent-factory -- --tags structural
```

## Live exercises

`scenarios.json` contains six requests: an adjacent ordinary coding question, a proprietary incident brief, no customization, justified isolated ledger specialist, substantial `spec-author` migration, and buried Fabric rules/contradictions in `spec-creator`. These use real model generation, not a scripted primitive classifier.

The optional `run-live.mjs` only stages fixtures and launches the native CLI; it is not another judge/evaluation engine or factory orchestration system. It selects an **eval-only** restricted file-tool profile, omits unrestricted path/URL flags, disables built-in MCPs/remote export, keeps default model settings, and verifies fixture hashes. It does not install that profile in the production factory.

```powershell
$env:COPILOT_BIN = (Get-Command copilot.ps1).Source
node .\evals\packs\agent-factory\run-live.mjs all C:\Path\To\Fresh\Run
```

The run directory must be new. Reports/logs and generated artifacts remain there. Native permission filtering is not claimed to be an OS sandbox or to prevent hostile filesystem races. No actual ledger server is executed. Use an actual sandbox for stronger confinement. Do not substitute Eval Pilot's unrestricted `--allow-all` live runner while claiming the same boundary.

The launcher verifies immutable staged inputs, zero files in the no-customization/adjacent cases, and no factory skill invocation on the adjacent question. It records observed model IDs and tool calls without overriding model defaults. **Semantic acceptance still requires inspecting actual outputs**, not treating exit code, file existence, hash preservation or fixture assertions as proof of domain correctness.

## Golden rules

For the `spec-author` migration, inspect the original source and generated knowledge/output for:

- EARS FRs, nested `AC-<FR>.<n>` criteria, evidence discipline and justified section selection.
- Draft/published status/version consistency, explicit publish approval, no draft changelog or mid-draft bump.
- Immutable prior-published IDs, pending deletions restored as publish-time stubs, transactional cross-reference updates.
- Required output contracts, product/technical/mixed scope distinctions and meaningful quality rubrics.
- Source-to-destination migration evidence and unresolved contradictions; no fixed five-agent pipeline.

For Fabric, preserve feature-specific NFRs versus organizational baseline checkpoints, variable AC counts, metrics definitions, mandatory authoring contracts, useful deterministic input utilities and consolidation-before-cleanup ordering. Not executing a utility does not authorize removing its capability. Flag normative/example tensions and dated product assertions rather than invent guarantees, and verify cited source paths actually exist.

For the simple case, require the S0/S1/S2 definitions and evidence/inference separation in one narrow customization. For the specialist, require isolated reusable context, explicit verified tool constraints and stated hypothetical/runtime limits without invented MCP setup. No-customization must produce a useful task request and no files.

Compare an actual representative specification task using legacy, modernized and bare contexts where feasible. Match model/settings and distinguish interpretation of legacy context from native legacy runtime execution. A useful ablation removes only one questionable resource and repeats that task. Missing metrics/runs are unverified, never passing.

## Recorded results

Observed on **2026-10-07**, Windows, Node **24.14.1**, Copilot CLI **1.0.86-1**. Live runs inherited the local default **`gpt-5.6-sol`**, not the newer models documented in the freshness reference. No model pin or alternative judge was added.

The original implementation's offline checks and native Copilot discovery passed. SHA-256 checks found **zero changes among 118 preserved legacy/source/installed files** at that time. Installation was subsequently simplified to `init.cmd`; the standalone installer and its regression suite were removed. The current five structural checks remain, and live fixtures now copy the canonical skill directly into fresh workspaces.

### Factory behavior

| Scenario | Observed result |
| --- | --- |
| Ordinary TypeScript question | No files, no tool calls, no factory activation |
| Reusable incident brief | One skill preserving S0/S1/S2 distinctions and evidence versus inference |
| Ordinary coding already covered by the host | Useful task request; zero artifacts |

| Substantial `spec-author` migration | One skill and five knowledge references, plus source-mapped migration evidence; no fixed five-agent pipeline |
| Roo/Fabric `spec-creator` migration | One skill, six references, three consumer templates and two optional original utilities, plus migration evidence; no Roo persona topology |

The first migration attempts were **not clean passes**. `spec-author` initially selected a subordinate drafter's PATCH rule over the explicitly canonical V10/V11 lifecycle and retained a generic execution routine. Fabric initially dropped useful DOCX/VTT utilities because execution was out of scope and cited one incorrect source path. Factory guidance was strengthened and the real factory was invoked again against copied outputs and unchanged originals; generated files were not manually repaired and mislabeled as model success.

The refined specification migration follows classified re-draft arithmetic and retains required approvals without the generic numbered reasoning routine. The Fabric refinement retained both utility scripts **byte-for-byte**, documented dependencies, parsing limitations and overwrite/install permissions without executing them, and corrected its provenance: **22 cited legacy paths exist**. Other Fabric domain rules/templates received source/static inspection, not an actual Fabric authoring or Roo runtime test.

### Actual specification comparison

All contexts received the same task: create a first-draft product PRD for an owner-only Tenant Activity Digest; reduce the supplied 20-minute awareness baseline to 5 minutes within 30 days using an opt-in survey; preserve tenant isolation and an explicit unavailable state; leave sample size/rollout date unresolved; select no implementation stack. Structure selection was preapproved. The same restricted file-only author and inherited model settings were used.

| Context | Deliverable words | Source-specific conventions observed |
| --- | ---: | --- |
| Original `spec-author` knowledge | 2,092 | Exact initial draft metadata, EARS FRs, nested AC IDs and OQ identifiers |
| Refined modern knowledge | 1,792 | The same tested conventions; source-specific questions remain explicit |
| Bare model | 2,173 | Useful conventional PRD, but no prescribed version, EARS form, nested AC IDs or OQ identifiers |
| Modern, lifecycle reference physically omitted | 2,495 | Initial-draft conventions still present in the root/other retained knowledge |

Actual documents were inspected for the supplied outcome, authorization/tenant boundary, unavailable-data distinction, unresolved decisions, no changelog and no technical-contract sections. Phrase checks alone were not treated as sufficient. These are single-sample **knowledge-context comparisons**, not executions of the original five-agent runtime or a statistically supported quality ranking.

The creation-only ablation does **not** show that update/publish lifecycle knowledge is dispensable: those operations were not exercised by that task, and the root still contains initial-draft invariants. The detailed resource remains available selectively rather than always loaded.

A separate live update exercised that resource: from a published `1.4.2` spec, an approved additive FR-07 opened **`1.5.0-draft`**, not PATCH. Required nested criteria were added, every unrelated byte (including deliberate typos and existing IDs) remained unchanged after isolating the authorized addition/metadata, and the existing changelog was untouched. This checks classified re-draft/minimal-edit behavior, not publication or deletion-ledger recovery.

The original factory entry body was **467 whitespace-delimited words** against its 600-word project budget; removing the installation-only resource link shortened it further. The original specification pack offers 18 Markdown files / 42,173 words; refined reusable knowledge offers six / 6,756, excluding its migration record. These are **available on-disk text**, not measured prompt tokens, consumption or cost; selective loading and runtime context differ.

### Limits

Codex/Claude native discovery/execution, real ledger integration/enforcement, script execution, and actual Fabric authoring remain unverified. Advanced publication/deletion-ledger transitions require further behavioral cases and host-state validation. Native tool/path controls are not an OS sandbox. Model generation can still omit or misinterpret rules; source-grounded inspection remains necessary.

Restoring the existing Eval Pilot engine dependencies reported 15 pre-existing audit findings (5 moderate, 8 high, 2 critical) and its successful build emitted the existing CJS `import.meta` warning. No unrelated dependency upgrades were made.

Raw native logs, copied inputs and generated outputs stay in the session's scratch artifacts, not committed fixture trees. `scenarios.json` and the launcher reproduce the primary factory requests; comparative prompts/method and observed limits are recorded above. Missing runs are unverified, never passing.
