# Review and Editing

Use this checklist when you finish a draft, when you edit an existing brief, and after every round of revisions. Fix every failing item. Do not just report it.

## Quality Checklist

1. **Headings:** content-descriptive, short, and neutral. No template labels or instructional parentheticals.
2. **Distinctness:** the title, summary, and problem do not overlap, and each section does only its own job. In a scope-brief, Problem Scope and Solution Scope stay distinct.
3. **"So what?":** every paragraph changes *this audience's* decision or understanding. For non-expert readers, orientation and definitions pass.
4. **Duplication:** each point appears once, where it fits best. That includes caveats and evidence limits: one statement, not a disclaimer in every section.
5. **Filler:** no introductory or bridging paragraphs, no internal "in conclusion," no unexplained hedging, no narration of the source files ("the funding request says…"), and no comments on the brief's own status.
6. **Length:** use the audience band as a review trigger. Remove filler and repetition. Never cut load-bearing content or merge distinct concepts.
7. **Links:** zero markdown links and zero bare URLs. Sources are described in words.
8. **Markdown:** headings, not bold, for structure; H1 only for the title; no skipped levels; `-` list markers; no HTML.
9. **Championing:** each section survives the 30-second "explain it to my boss" test and carries at least one repeatable outcome statement.
10. **Optional-section gate:** each optional section has source support and fits the maturity. Background and definitions for non-expert readers stay. The evidence log appears only on request, and it never cites working files.
11. **Readability:** sentences of 25 words or fewer, one point per paragraph, the lead first, plain words, active voice.
12. **Closing:**
    - The closing type matches the source signals and meets its content requirements.
    - The heading is content-descriptive.
    - There is no phantom ask.
    - The summary's last sentence agrees with the closing.
    - A scope-brief without a closing contains no leaked decision or approval language.
13. **Terminology:** one name per concept. Unnamed entities have a single provisional name flagged as an open question. Terms are defined on first mention where the audience needs it. Renames reach every occurrence.
14. **Unverified quantities:** every specific number traces to a source. Otherwise, make it qualitative or label it as an estimate with its basis.
15. **AI-isms:** apply all of `writing-style.md`'s AI-ism categories, including the writer-scaffolding class. Recognize the class rather than grepping for strings.
16. **Posture and status:** settled decisions are stated declaratively, and open items are not presented as decided.

## Editing an Existing Brief

- Read the whole brief and any source material first. Infer its type, maturity, audience, closing, and posture. If the audience is unclear, ask.
- Preserve the author's content and decisions. Change only what the request or the checklist requires. Do not re-architect a brief the user asked you to polish.
- Treat feedback as a statement of intent, not final copy. Apply the underlying fix in the brief's voice and make it consistent with the rest of the document.
- When an edit renames something or changes a fact, propagate it everywhere it appears.
- After editing, run the checklist on the whole brief, not just the changed passages. Pay particular attention to items 13–15.

## Review Feedback

Classify each comment, then act on it:

| Class | Examples | Action |
|---|---|---|
| Minor | Wording, formatting, naming, a dropped qualifier, AI-ism cleanup | Edit directly, then re-run the relevant checks (especially 13–15). |
| Major: composition | Structure, tone, framing, audience recalibration, adding or removing a section, a change of closing type | Rework the affected sections, then run the full checklist. |
| Major: strategy | Options, KPIs, milestones, financials | Re-derive those sections from the sources, then update the summary and closing to match. |
| Major: evidence | Source interpretation, contradictions, assumptions, authorship, decision status | Re-read the sources, fix the claims, and re-check the maturity, posture, and every section that depended on them. |

- Batch related comments into one revision.
- If the same comment comes back without converging, raise it with the user instead of re-revising blindly.
- After about five review rounds, check in with the user: continue, pause, or wrap up.
- If a review tool cannot resolve a thread, still make the content fix, and tell the user which threads they need to close by hand.
